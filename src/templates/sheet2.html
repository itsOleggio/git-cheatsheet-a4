Формат сообщения · Conventional Commits 1.0 · SemVer 2.0
feat(cart)!: add promo code field
typeтип изменения; список задаёт конфиг команды
(scope)модуль или область, необязательно
!ломает обратную совместимость
subjectсуть изменения, коротко

Как это выглядит в историиgit log --oneline --graph

mainfeature/SHOP-142-cart-promo-codehotfix/1.4.1-payment-timeoutтег релиза● залитый — merge-коммит

Типы коммитов

Спецификация задаёт только feat и fix, остальные типы — соглашение Angular / commitlint и версию сами не меняют. * PATCH — по правилам semantic-release по умолчанию.

Хорошо и плохо

Правила

Повелительное наклонение: «add», не «added»/«adds». Проверка: «If applied, this commit will…»
Строчная буква, без точки в конце — проверяет commitlint
Длина заголовка: ~50, не больше 72 (git); commitlint допускает до 100
Один коммит — одно изменение. Сложно назвать — значит, коммит пора делить
Язык — как принято в команде, обычно английский
Тикет — в футере Refs: SHOP-142; scope — это модуль, а не номер задачи
Тело — после пустой строки: зачем, а не что

Версия из коммитов

fix:1.4.0 → 1.4.1patch feat:1.4.1 → 1.5.0minor feat!:1.5.0 → 2.0.0major
